# Будущие курсы

Направления, которые стоит добавить после основной программы (блоки 0–11 из [ROADMAP.md](ROADMAP.md)). Это предложения, а не обязательства: состав и порядок решает автор курса.

Отбор шёл по трём признакам:

- пригодится в той работе, под которую строился основной курс: сайты на JS и PHP, легаси, PostgreSQL и MS SQL;
- закрывает то, без чего знания из основного курса трудно применить на практике;
- ложится на формат платформы: короткая теория, лестница заданий, проект.

Формат уроков тот же, что в основной программе: вопрос, пропуски, починка, по тестам, план, с нуля, карточки.

## A. Git и работа в команде

**Зачем.** Любая работа с чужим кодом идёт через Git. Легаси-проекты особенно: там история изменений часто единственная документация.

**Нужно знать заранее:** ничего, можно начинать параллельно с основной программой.

| Урок | Содержание | Идеи заданий |
|---|---|---|
| Три состояния файла | Рабочая папка, индекс, коммит; `status`, `add`, `commit`, `diff` | Довести репозиторий до заданного состояния |
| История | `log`, `show`, `blame`; как читать чужую историю и искать, когда появилась строка | Найти коммит, который сломал функцию |
| Хорошие коммиты | Один коммит — одно изменение, текст сообщения, `add -p` | Разделить большую правку на три осмысленных коммита |
| Ветки и слияние | `branch`, `switch`, `merge`, быстрое слияние и коммит слияния | Слить две ветки, получить заданный граф |
| Конфликты | Откуда берутся, как читать разметку конфликта, как решать | Разрешить три конфликта разной сложности |
| Удалённый репозиторий | `clone`, `fetch`, `pull`, `push`, отслеживаемые ветки | Синхронизировать локальный и «удалённый» репозиторий |
| Отмена | `restore`, `reset`, `revert`, `stash`, `reflog`; что безопасно, а что переписывает историю | Вернуть случайно удалённый коммит |
| Запрос на слияние | Ветка под задачу, ревью, правки по замечаниям, `rebase` обзорно | Проект: довести задачу от ветки до слияния |

**Движок.** Новый тип задания `git`: для задания создаётся временный репозиторий из сценария, ученик вводит команды в поле-терминале, после каждой показывается граф коммитов. Проверка — по итоговому состоянию: ветки, содержимое файлов, число коммитов. Команды выполняются только из разрешённого списка (`git …`, `ls`, `cat`) в отдельной папке.

## B. Командная строка, Linux и Docker

**Зачем.** Сайт на PHP живёт на сервере с Linux. Платформа сама запускается через Docker, и блок 8 добавит в неё два сервера баз — понимать, что при этом происходит, полезно уже для самого курса.

**Нужно знать заранее:** блок 7 «PHP и веб».

| Урок | Содержание |
|---|---|
| Оболочка | Пути, `cd`, `ls`, `cat`, `less`, шаблоны имён, история команд |
| Файлы и права | `cp`, `mv`, `rm`, `chmod`, `chown`; почему PHP «не может записать файл» |
| Потоки и конвейеры | Перенаправление, `grep`, `sort`, `uniq`, `wc`, `head`, `tail` — разбор журнала одной строкой |
| Процессы и сеть | `ps`, `kill`, порты, `curl`, `ss`; «адрес уже занят» и что с этим делать |
| Удалённый сервер | SSH, ключи, `scp`, `rsync` |
| Веб-сервер | Как запрос доходит до PHP: nginx или Apache и PHP-FPM, журналы ошибок |
| Docker: контейнеры | Образ и контейнер, `run`, `exec`, `logs`, тома, порты |
| Docker Compose | Несколько сервисов, сеть между ними, переменные окружения. Разбор `docker-compose.yml` платформы |
| Проект | Развернуть гостевую книгу из блока 7 в контейнерах: веб-сервер, PHP, база |

**Движок.** Терминал из курса A подходит и здесь. Для уроков про Docker и веб-сервер автопроверка ограничена: задания выполняются на машине ученика, а платформа проверяет результат запросом по адресу (`curl` с ожидаемым ответом) или просит вставить вывод команды.

## N. Программирование с ИИ-ассистентом

**Зачем.** Ассистент легко пишет код — и так же легко закрепляет исходную проблему: читать умею, писать нет. Курс о том, как пользоваться им, не теряя навык.

**Нужно знать заранее:** блок 5.

| Урок | Содержание |
|---|---|
| Что ассистент делает хорошо и плохо | Шаблонный код и объяснения против знания твоего проекта и актуальных версий |
| Постановка задачи | Контекст, ограничения, пример входа и выхода — та же декомпозиция из блока 0, только вслух |
| Проверка ответа | Чтение чужого кода как ревью: что проверить, прежде чем принять |
| Режим обучения | Просить подсказку, а не решение; объяснение своего кода; разбор ошибок |
| Границы | Секреты и чужой код в запросах, лицензии, выдуманные функции и пакеты |

**Движок.** Не нужен. Задания — на ревью: дан «ответ ассистента» с ошибками трёх видов (не работает на границе, уязвимость, несуществующая функция), нужно найти и исправить.
