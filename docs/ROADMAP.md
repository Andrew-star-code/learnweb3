# Дорожная карта

Документ для того, кто продолжит работу над платформой — в новой сессии или вручную. В нём: что уже сделано, как устроено содержимое, что осталось написать по каждому блоку и что для этого нужно доделать в движке.

Состояние на момент последнего обновления: **49 уроков, 287 заданий, блоки 0–6 закрыты полностью.** Следующий — блок 7 «PHP и веб».

## 3. Как устроено содержимое

Это раздел, который нужно прочитать перед тем, как писать новый урок.

### Файлы

```text
content/course.php                 программа: блоки, порядок уроков, список «скоро»
content/<блок>/<урок>/lesson.md    теория
content/<блок>/<урок>/tasks.php    задания и карточки
```

Чтобы добавить урок: создать папку с двумя файлами и дописать её имя в массив `lessons` нужного блока в `content/course.php`. Темы, которые ещё не написаны, лежат в массиве `planned` и показываются на главной с меткой «Скоро».

### lesson.md

- Первая строка `# Заголовок` — название урока.
- Поддерживается подмножество Markdown: заголовки, абзацы, списки в один уровень, таблицы, цитаты `>` (отображаются как жёлтые врезки), блоки кода с указанием языка, в строке — `код`, **жирный**, *курсив*, ссылки. Код с обратной кавычкой внутри оборачивается в двойные обратные кавычки. Символ `|` внутри ячейки таблицы пишется как `\|`.
- Последний раздел — `## Глубже` со ссылками.
- Языки блоков кода: `js`, `php`, `html`, `css`, `sql`, `json`, `text`.
- Блок, открытый строкой ` ```php versions `, получает кнопку «Запустить на PHP 8.3 и 7.0». Если в примере нет `<?php`, он добавляется при запуске. Пример должен выполняться сам по себе, без кода из соседних блоков.

Вложенных списков и картинок рендерер не умеет — см. `src/Markdown.php`.

### tasks.php

Файл возвращает массив с ключами `tasks` и `cards`.

Общие поля задания: `id` (уникален в пределах урока), `type`, `title`, `text` (Markdown).

| Тип | Дополнительные поля |
|---|---|
| `quiz` | `options` (массив строк), `answer` (номер с нуля), `explain` |
| `plan` | `reference` — эталонный разбор в Markdown |
| `code` | `kind`, `lang`, `starter`, `tests`, `hints` (массив), `solution` |

`kind` задаёт метку и место в лестнице: `fill` (дописать пропуски `___`), `fix` (починить), `tests` (написать по тестам), `scratch` (с нуля), `project`.

`lang`: `js`, `html` (любое задание с предпросмотром, включая CSS и браузерный JS), `php`.

Флаги:

| Флаг | Что делает |
|---|---|
| `noSolution` | Решение не открывается. Для проектов |
| `bootstrap` | К предпросмотру подключается Bootstrap 5 (CSS и JS) |
| `storage` | Показывает кнопку «Очистить хранилище» |
| `hangs` | Заготовка намеренно зависает; `tools/verify.js` её не запускает |
| `php` | `'7'` — выполнять PHP-задание на PHP 7.0 вместо 8.3; `'both'` — проверять на обеих версиях, задание засчитывается, только если тесты прошли на каждой |

`cards` — массив пар `[вопрос, ответ]`. Карточки попадают в колоду при первом открытии урока.

### Что доступно в тестах

**JS (`lang: js`)** — тесты выполняются в одной функции с кодом ученика и видят всё, что в нём объявлено:

```js
test('название', () => { … });          // функция может быть async
assertEqual(actual, expected, message);  // глубокое сравнение
assert(condition, message);
assertThrows(fn, message);
logs                                     // массив строк, выведенных через console.log
```

**Предпросмотр (`lang: html`)** — тесты выполняются внутри рамки после события `load`:

```js
test, assert, assertEqual
$(selector)          // элемент; понятная ошибка, если его нет
$$(selector)         // массив элементов
css(target, prop)    // вычисленное значение стиля
px(target, prop)     // то же числом
box(target)          // getBoundingClientRect
text(target)         // текст без лишних пробелов
await setWidth(px)   // изменить ширину окна предпросмотра
await wait(ms)
await until(() => условие, 'сообщение')   // дождаться изменения на странице: запросы, таймеры
click(target), type(target, value), submit(form)
```

Функции и переменные верхнего уровня из `<script>` ученика доступны тестам по имени.

**PHP (`lang: php`)** — тесты пишутся без `<?php` и выполняются после подключения кода ученика:

```php
test('название', function () { … });
assert_eq($expected, $actual, $message);   // строгое сравнение; порядок аргументов — ожидаемое первым
assert_true($value, $message);
assert_throws($fn, 'ИмяКласса', $message);  // возвращает пойманное исключение — можно проверить текст
output()                                    // всё, что код напечатал через echo
```

Обвязка лежит в `runner/lib.php`. **Этот файл и `runner/server.php` должны оставаться совместимыми с PHP 7.0.**

### Правила, выведенные на практике

- Любая проверка, зависящая от ширины, сначала вызывает `setWidth`. Ширина предпросмотра у ученика зависит от его экрана.
- Цвета в заданиях задаются как `rgb(…)`: в таком виде браузер отдаёт вычисленные стили, и их можно сравнивать строкой.
- Поле `type="number"` без `step` не пропускает дробные значения — `submit()` молча не сработает.
- В тестах предпросмотра нельзя писать `</script>`.
- Если заготовка не отменяет отправку формы, рамка уходит на другую страницу и тест завершается по таймауту через 8 секунд. Это ожидаемо, но тест «отправка отменена» лучше ставить последним.
- Асинхронные тесты JS-заданий должны быть короткими: исполнитель останавливает код через 3 секунды на всё задание. Паузы — десятки миллисекунд.
- Тесты заданий с `fetch` начинают с `POST /api/demo/reset`, а ошибку сервера заказывают через `POST /api/demo/fail-next`. Чтобы посчитать запросы ученика, тест подменяет `window.fetch` обёрткой, а сам ходит в API через сохранённый оригинал.
- Страница, которая сама загружает данные при открытии, может дорисовать их уже после начала теста. Первый тест сначала дожидается конца этой загрузки (`until`), и только потом сбрасывает данные.
- Проверить «восстановление после перезагрузки» напрямую нельзя. Задание требует именованную функцию (`load()`, `restoreDraft()`), тест кладёт данные в хранилище и вызывает её.
- В каждом уроке, кроме проектов и обзорных: 1–2 вопроса, по одному заданию каждой ступени лестницы, перед заданием «с нуля» — задание «План». 3–6 карточек.
- Файл с тестами PHP выполняется со `strict_types=1`. Это важно: строгий режим действует для файла, из которого идёт вызов, поэтому тест «строка вместо числа даёт TypeError» работает только так.
- Заготовка PHP-задания с вызовом функции внизу файла («для проверки руками») при пустом теле функции с объявленным типом результата падает с фатальной ошибкой раньше тестов. Ученик видит понятное сообщение PHP, но не список тестов. Для заданий «по тестам» и «с нуля» демонстрационный вызов лучше не ставить или закомментировать.
- Несколько неймспейсов в одном PHP-задании записываются в фигурных скобках (`namespace App\Models { … }`), а код вне их — в блоке `namespace { … }`. Тесты обращаются к классам по полному имени с ведущей косой чертой.
- В PHP-тестах можно создавать временные файлы (`sys_get_temp_dir()`), как в задании про автозагрузчик; в конце теста их нужно удалить.
- Примеры — вокруг одной легенды: кофейня «Зерно», каталог, заказы, корзина.
- В легаси-контексте (старый Bootstrap, `var`, CommonJS, jQuery) цель — научить читать и безопасно править, а не писать новое в старом стиле.

### Проверка перед коммитом

```bash
node tools/verify.js                              # JS-задания: решение проходит, заготовка нет
php -S 127.0.0.1:8000 -t public public/index.php  # в соседнем терминале
node tools/verify-html.js                         # задания с предпросмотром, нужен Playwright
php tools/verify-php.php                          # PHP-задания
```

Все три скрипта должны завершаться строкой «Всё в порядке». Задания с флагом `php => '7'` или `'both'` скрипт `verify-php.php` полностью проверяет только внутри Docker: `docker compose exec app php tools/verify-php.php`. Без контейнера задания `'both'` проверяются на 8.3, а в конце печатается число непроверенных на PHP 7. После правок в `runner/lib.php` стоит убедиться, что он работает на PHP 7.0: `docker compose exec php7 php -l /runner/lib.php`.

## 4. Оставшиеся блоки

Для каждого блока: уроки, ключевые задания и то, что нужно доделать в движке. Оценка объёма — в уроках.

### Блок 4. Асинхронность и сеть — готов

Шесть уроков: event loop, промисы, async/await, HTTP, fetch и JSON, проект «Список дел с сервером».

Учебное API:

| Запрос | Что делает |
|---|---|
| `GET /api/demo/products` | Список товаров; `?q=` — поиск по названию |
| `GET /api/demo/products/{id}` | Один товар или `404` |
| `GET /api/demo/todos` | Список дел |
| `POST /api/demo/todos` | Создать дело, тело — JSON `{ "text": "…" }`, ответ `201` |
| `DELETE /api/demo/todos/{id}` | Удалить, ответ `204` |
| `POST /api/demo/reset` | Вернуть список дел в исходное состояние (для тестов) |
| `POST /api/demo/fail-next?times=N` | Следующие N запросов вернут `500` (для тестов) |

Любой запрос понимает `?delay=мс` (до 3000) и `?fail=код`. API открыто для любых источников и не требует токена — оно хранит только игрушечные данные в таблицах `demo_todos` и `demo_state` рядом с прогрессом.

Что можно добавить позже: изменение дела (`PATCH`), постраничный вывод товаров (`?page=`), отмена запроса через `AbortController` — в уроке про fetch она только упомянута в плане и в текст не вошла.

### Блок 5. Ядро PHP — готов

Восемь уроков: типы и переменные, массивы, функции, строки, ООП, неймспейсы и автозагрузка, исключения, проект «Разбор журнала веб-сервера». Изложение построено на сравнении с JavaScript; в каждом уроке есть врезка «В PHP 7».

Что осталось за рамками и может пригодиться позже:

- **Задания из нескольких файлов** (поле `files`). Неймспейсы обошлись фигурными скобками в одном файле, автозагрузчик — временными файлами в тестах. Для шаблонов и MVC в блоках 7 и 10 поле всё же понадобится.
- **Composer** в уроке про автозагрузку описан, но заданий на него нет: это тема будущего курса C.
- **Генераторы, `static`, трейты, абстрактные классы, `match` и `enum` подробно** — в уроках не разобраны или только упомянуты. Трейты и абстрактные классы стоит добавить в урок про ООП или в блок «Архитектура», когда появится пример, где они нужны.

### Блок 6. Легаси PHP — готов

Четыре урока: что появилось в какой версии (синтаксис против функций, полифилы, `version_compare`), что молча изменилось в PHP 8 (сравнение числа со строкой, предупреждения, ставшие исключениями, порядок склейки и сложения, функции с новыми ответами), перенос кода в обе стороны (таблица замен, порядок осовременивания), чтение и правка легаси (`include` и `global`, признаки возраста, склейка SQL и вывод без экранирования, правило минимальной правки, вынос расчёта из разметки). Все утверждения о различиях версий сверены запуском на PHP 8.3.6 и 7.0.33.

Задания выполняются на PHP 7.0 (`php => '7'`) или на обеих версиях (`php => 'both'`). Образ `php:7.0-cli` давно без поддержки — для учебного запуска кода на своей машине это допустимо, наружу контейнер не смотрит.

Правила, выведенные при написании блока:

- Пример `php versions` хорош, когда колонки **различаются**. Если вывод совпадает, в тексте должно быть сказано, зачем пример запускать.
- Заготовка задания «на двух версиях» может падать на одной версии и проходить часть тестов на другой. `verify-php.php` считает её корректной, если хотя бы на одной версии не прошли все тесты.
- Предупреждения и замечания в выводе PHP 8 и PHP 7 называются по-разному (`Warning: Undefined array key` и `Notice: Undefined index`). Тесты не должны сравнивать вывод, где они могут появиться.
- Чтобы проверить, что ученик «не тронул остальное», тест сравнивает итоговый HTML страницы через `output()` с зафиксированным образцом (задание `reading/extract-logic`).

Что осталось за рамками: PHP 7.1–7.3 как отдельные исполнители (сейчас разница между ними описана текстом), `mysql_*` и `mysqli_*` вживую — появятся вместе с базой в блоке 8, автоматические инструменты (Rector, PHPCompatibility) — только ссылками.

### Блок 7. PHP и веб (6 уроков)

| Урок | Содержание |
|---|---|
| Запрос и ответ | `$_SERVER`, `$_GET`, `$_POST`, заголовки, коды ответа, перенаправление, встроенный сервер |
| Формы и валидация | Приём формы, проверка на сервере, повторный показ формы с ошибками и введёнными значениями, схема «отправка → перенаправление → показ» |
| Сессии и cookies | `setcookie`, `$_SESSION`, как сессия устроена внутри, флеш-сообщения, время жизни |
| Загрузка файлов | `$_FILES`, проверка типа и размера, безопасное имя, куда класть |
| Шаблоны | Отделение логики от разметки, `htmlspecialchars`, макет и вставки (пример — `src/View.php` платформы) |
| Проект | Гостевая книга: форма, проверка, хранение в файле или SQLite, вывод с экранированием |

**Нужно в движке — самая крупная доработка курса.** Сейчас PHP выполняется как консольный скрипт, а здесь нужен PHP, отвечающий на HTTP-запросы. Варианты:

1. **Имитация запроса в тестах** (проще): обвязка заполняет `$_GET`, `$_POST`, `$_SERVER`, подключает код ученика и сравнивает вывод. Заголовки перехватываются обёрткой над `header()` или через `xdebug_get_headers` / `headers_list` в режиме `php-cgi`.
2. **Настоящий запуск** (нагляднее): для задания поднимается `php -S` на временном порту в отдельной папке, предпросмотр открывает его в рамке, тесты делают запросы. Нужны управление жизненным циклом процесса и проброс порта из контейнера.

Разумно начать с первого варианта, а второй сделать для проекта и для блока «Архитектура».

### Блок 8. Базы данных: PostgreSQL и MS SQL (8 уроков)

| Урок | Содержание |
|---|---|
| SELECT и фильтры | `WHERE`, `ORDER BY`, ограничение числа строк, `NULL`, `LIKE`, `IN`, `BETWEEN` |
| JOIN | Внутреннее и внешние соединения, связи один-ко-многим и многие-ко-многим |
| Группировки | `GROUP BY`, агрегаты, `HAVING` |
| Подзапросы и оконные функции | `EXISTS`, CTE, `ROW_NUMBER`, нарастающий итог |
| Транзакции и индексы | `BEGIN`/`COMMIT`, уровни изоляции обзорно, зачем индекс, план запроса |
| Отличия диалектов | `LIMIT` и `TOP` / `OFFSET FETCH`, `SERIAL` и `IDENTITY`, `RETURNING` и `OUTPUT`, кавычки и квадратные скобки, строки и даты, переменные и процедуры T-SQL |
| PDO: pgsql и sqlsrv | Подключение, подготовленные запросы, транзакции, режим ошибок, типичные проблемы с драйверами; отдельно — MS SQL из PHP 7 |
| Проект | Блог с CRUD на PDO |

**Нужно в движке:**

- В `docker-compose.yml` — сервисы `postgres` и `mssql`. MS SQL занимает около 2 ГБ памяти, поэтому его стоит вынести в профиль (`profiles: [mssql]`), чтобы не держать поднятым во время изучения JS.
- Учебная база «магазин» (клиенты, товары, заказы, позиции заказов) с одинаковым содержимым на обоих серверах и кнопкой сброса в исходное состояние.
- В образ `app` — расширения `pdo_pgsql` и `pdo_sqlsrv`. Значит, вместо готового образа `php:8.3-cli` понадобится свой `Dockerfile`. Для MS SQL нужен драйвер ODBC от Microsoft.
- **Новый тип задания `sql`**: редактор запроса, выбор сервера или оба сразу, результат таблицей (двумя таблицами рядом). Проверка — сравнение результата с результатом эталонного запроса, с учётом или без учёта порядка строк.
- Запросы ученика выполнять от пользователя с ограниченными правами и в транзакции с откатом, чтобы задание нельзя было сломать.
- Страница «SQL-песочница» со схемой базы и планом выполнения запроса.
- Подключение PDO из PHP 7.0 к MS SQL: проверить, существует ли рабочая версия `pdo_sqlsrv` для 7.0. Если нет — честно описать это в уроке как типичную легаси-проблему и показать на 7.4 или через `dblib`.

### Блок 9. Безопасность (5 уроков)

| Урок | Содержание |
|---|---|
| XSS | Отражённый и сохранённый, экранирование при выводе, контекст (HTML, атрибут, JS), CSP обзорно |
| CSRF | Суть атаки, токены, `SameSite`. Живой пример — `src/Security.php` платформы |
| SQL-инъекции | Как работает, подготовленные запросы, почему «экранирование руками» не спасает |
| Пароли | `password_hash`, `password_verify`, почему не MD5 и не SHA, соль, перебор |
| Авторизация и роли | Вход, сессия, проверка прав на каждом действии, типовые ошибки контроля доступа |

Формат заданий — «найди и закрой уязвимость»: дан работающий, но уязвимый код, тесты проверяют и сохранение поведения, и то, что атакующий запрос больше не проходит. Опирается на имитацию запросов из блока 7 и на базу из блока 8.

## 6. Известные ограничения и долги

- **Проверка только в Chromium.** В Firefox и Safari платформа не запускалась.
- **Внешние ссылки в блоках «Глубже» не проверены**: адреса написаны по памяти, из среды разработки эти сайты были недоступны. Нужен проход по всем ссылкам и скрипт, который делает это автоматически.
- **Модули JS без заданий с кодом**: редактор выполняет один файл. Решается полем `files`.
- **У `SyntaxError` в JS-заданиях нет номера строки**: код выполняется через `new Function`, и браузер не сообщает позицию.
- **Образец в заданиях по вёрстке приходит в браузер вместе с решением.** Для одного ученика на своей машине это не проблема, но «спрятанным» решение считать нельзя.
- **Прогресс привязан к `id` задания.** Переименование `id` или папки урока обнуляет прогресс по ним.
- **Нет переноса прогресса** между машинами. Достаточно скопировать `data/progress.sqlite`; кнопки экспорта нет.
- **Встроенный сервер PHP** рассчитан на одного пользователя. Для учебной платформы этого хватает.
- **Файлы в `data/` при запуске через Docker на Linux принадлежат root.**
- **Автоматических тестов самого движка нет** — только проверка содержимого.
- **`tools/verify-html.js` пишет в прогресс**: после него в `data/` остаются черновики заготовок. Перед проверкой на своей машине стоит сохранить `data/progress.sqlite`, либо научить скрипт работать с отдельной базой.
- **Необработанный отклонённый промис в JS-задании** ученик не видит: исполнитель возвращает результат один раз и поздние ошибки теряет.

## 7. Идеи для платформы

Не входят в исходный план. Решать с автором курса.

- Страница статистики: пройдено по блокам, серия дней, слабые темы по карточкам и числу попыток.
- Свои карточки и заметки к урокам.
- Повторение заданий, а не только карточек: вернуть через неделю задачу, решённую с подсказками.
- Отладчик в заданиях JS: пошаговое выполнение с просмотром переменных.
- Сравнение своего решения с эталонным бок о бок после прохождения.
