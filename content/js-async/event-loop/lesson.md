# Event loop: как JavaScript делает несколько дел

JavaScript выполняет код **в один поток**: в каждый момент работает ровно одна функция. При этом страница умеет ждать ответа сервера, отсчитывать таймеры и реагировать на щелчки одновременно. Противоречия нет — и понять, почему, значит понять всю асинхронность.

## Долгие дела делает не JavaScript

Таймер отсчитывает браузер. Запрос по сети отправляет браузер. JavaScript только говорит: «когда закончишь — вызови вот эту функцию», и идёт дальше.

```js
console.log('1');

setTimeout(() => {
  console.log('2');
}, 1000);

console.log('3');
```

Вывод: `1`, `3`, а через секунду `2`. `setTimeout` не останавливает программу на секунду. Он регистрирует функцию и немедленно возвращает управление.

## Очередь и цикл

Когда таймер сработал или пришёл ответ, функция не выполняется сразу. Она встаёт в **очередь задач**. Движок работает по простому циклу:

1. Выполнить текущий код до конца.
2. Взять из очереди следующую функцию.
3. Выполнить её до конца.
4. Повторять.

Этот цикл и называется event loop. Из него следуют два важных правила.

**Функция из очереди выполнится только после того, как закончится текущий код.** Даже с нулевой задержкой:

```js
setTimeout(() => console.log('таймер'), 0);
console.log('конец');
// конец
// таймер
```

`setTimeout(fn, 0)` означает не «сейчас», а «как только освободишься».

**Пока код выполняется, всё остальное ждёт.** Долгий цикл не даёт сработать ни таймерам, ни обработчикам щелчков, ни перерисовке страницы:

```js
setTimeout(() => console.log('таймер'), 100);

const start = Date.now();
while (Date.now() - start < 3000) { }   // три секунды страница не отвечает

console.log('цикл закончился');
// цикл закончился
// таймер — через три секунды, а не через 100 мс
```

Задержка в `setTimeout` — это минимум, а не гарантия. Зависшая вкладка — почти всегда такой цикл.

## Две очереди

Очередей на самом деле две, и у них разный приоритет:

- **микрозадачи** — обработчики промисов (`then`, код после `await`);
- **задачи** — таймеры, события, сеть.

После каждого куска кода движок сначала выполняет **все** микрозадачи и только потом берёт одну обычную задачу.

```js
setTimeout(() => console.log('таймер'), 0);
Promise.resolve().then(() => console.log('промис'));
console.log('код');
// код
// промис
// таймер
```

Порядок всегда такой: текущий код → микрозадачи → следующая задача.

## Результат нельзя вернуть «из будущего»

Самая частая ошибка новичка в асинхронном коде:

```js
function loadPrice() {
  let price;
  setTimeout(() => {
    price = 890;          // выполнится позже
  }, 100);
  return price;           // выполнится сейчас — undefined
}
```

`return` срабатывает до того, как значение появилось. Функция, результат которой будет готов позже, не может вернуть его обычным способом. У неё три пути:

- принять **колбэк** и вызвать его, когда значение готово;
- вернуть **промис** — следующий урок;
- быть **`async`-функцией** — через урок.

```js
function loadPrice(callback) {
  setTimeout(() => {
    callback(890);
  }, 100);
}

loadPrice((price) => console.log(price));
```

## Таймеры

```js
const id = setTimeout(fn, 1000);      // один раз через секунду
clearTimeout(id);                     // отменить

const timer = setInterval(fn, 1000);  // каждую секунду
clearInterval(timer);                 // остановить
```

`setInterval` не останавливается сам. Забытый `clearInterval` — источник утечек и «призрачных» обновлений на странице.
