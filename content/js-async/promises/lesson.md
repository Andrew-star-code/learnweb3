# Промисы

Колбэки работают, пока асинхронное действие одно. Когда их цепочка — загрузить пользователя, потом его заказы, потом товары заказа — колбэки вкладываются друг в друга, а обработка ошибок размазывается по всем уровням. Промис решает обе проблемы.

**Промис — это объект, который представляет результат, которого ещё нет.** Функция возвращает его сразу, а значение появится в нём позже.

## Три состояния

- **ожидание** — результата ещё нет;
- **выполнен** — есть значение;
- **отклонён** — есть ошибка.

Из ожидания промис переходит в одно из двух других состояний **один раз и навсегда**. Выполненный промис не может стать отклонённым или получить другое значение.

## Получить результат

```js
loadUser(42)
  .then((user) => {
    console.log(user.name);       // когда выполнится
  })
  .catch((error) => {
    console.log(error.message);   // если отклонится
  })
  .finally(() => {
    hideSpinner();                // в любом случае
  });
```

## Цепочки

`then` возвращает **новый промис**. Его значением становится то, что вернул обработчик. Поэтому шаги записываются друг под другом, а не вкладываются:

```js
loadUser(42)
  .then((user) => loadOrders(user.id))      // вернули промис — цепочка его дождётся
  .then((orders) => orders.length)          // вернули значение — оно уйдёт дальше
  .then((count) => console.log(count))
  .catch((error) => console.log(error));    // ловит ошибку любого шага выше
```

Два правила, на которых держится цепочка:

- Если обработчик вернул промис, следующий `then` дождётся его.
- Ошибка — отклонённый промис или `throw` внутри обработчика — пролетает через все `then` до ближайшего `catch`. Как исключение через вызовы функций.

### Потерянный return

Самая частая ошибка в цепочках:

```js
loadUser(42)
  .then((user) => {
    loadOrders(user.id);          // return забыт
  })
  .then((orders) => {
    console.log(orders);          // undefined
  });
```

Обработчик ничего не вернул — дальше ушло `undefined`, и цепочка не стала ждать `loadOrders`. То же самое с функцией, которая запускает цепочку, но не возвращает её: вызывающий код не сможет ни дождаться результата, ни поймать ошибку.

Правило: **в асинхронной функции промис всегда возвращается наружу.**

## Создать промис

Нужно редко — в основном чтобы обернуть старое API на колбэках.

```js
function delay(ms) {
  return new Promise((resolve) => {
    setTimeout(resolve, ms);
  });
}

function readFileAsync(name) {
  return new Promise((resolve, reject) => {
    readFile(name, (error, data) => {
      if (error) {
        reject(error);
      } else {
        resolve(data);
      }
    });
  });
}
```

`resolve(значение)` выполняет промис, `reject(ошибка)` отклоняет. В `reject` передают объект `Error`, а не строку.

Готовые промисы без ожидания: `Promise.resolve(значение)` и `Promise.reject(ошибка)`.

## Несколько промисов сразу

| Метод | Когда выполняется | Результат |
|---|---|---|
| `Promise.all([a, b])` | Когда выполнены **все**; отклоняется при первой ошибке | Массив значений в порядке промисов |
| `Promise.allSettled([a, b])` | Когда завершены все, с любым исходом | Массив `{ status, value }` или `{ status, reason }` |
| `Promise.race([a, b])` | Когда завершён **первый**, с любым исходом | Его значение или ошибка |
| `Promise.any([a, b])` | Когда выполнен первый успешный | Его значение |

Главный из них — `Promise.all`. Он запускает действия **параллельно**:

```js
const [user, orders] = await Promise.all([loadUser(42), loadOrders(42)]);
```

Два запроса по секунде займут секунду, а не две. Порядок результатов совпадает с порядком в массиве, а не с порядком завершения.

`Promise.race` удобен для ограничения времени: гонка между настоящим действием и таймером, который отклоняется.
