# Неймспейсы и автозагрузка

В проекте сотни классов. Двум из них рано или поздно захочется называться `User` или `Request`. А ещё каждый файл с классом нужно как-то подключить. Эти две задачи решают неймспейсы и автозагрузка — пара, на которой стоит любой современный PHP-проект.

## Неймспейс

Неймспейс — это «фамилия» класса. Полное имя состоит из неймспейса и короткого имени, разделённых обратной косой чертой.

```php
<?php
// файл src/Models/User.php

namespace App\Models;

class User
{
}
```

Полное имя этого класса — `App\Models\User`. В другом неймспейсе может жить другой `User`, и они не конфликтуют.

Объявление `namespace` — первая инструкция в файле (после `declare`). Принято: **один файл — один класс**.

## use

Чтобы не писать полное имя каждый раз, класс импортируют в начале файла:

```php
<?php

namespace App\Controllers;

use App\Models\User;
use App\Services\Mailer as Mail;       // с другим коротким именем

class UserController
{
    public function create(): void
    {
        $user = new User();            // вместо new \App\Models\User()
        $mail = new Mail();
    }
}
```

`use` ничего не загружает и не подключает. Это только сокращение имени — как `import` в JS, но без загрузки файла.

### Правила поиска имени

Внутри неймспейса имя без косой черты в начале ищется **относительно текущего неймспейса**:

| Запись внутри `namespace App\Controllers` | Что ищется |
|---|---|
| `new User()` | `App\Controllers\User` — если нет `use` |
| `new Models\User()` | `App\Controllers\Models\User` |
| `new \App\Models\User()` | Ровно `App\Models\User` |
| `new \DateTime()` | Встроенный класс PHP |

Отсюда частая ошибка: `Class "App\Controllers\DateTime" not found`. Встроенные классы живут в корневом неймспейсе, и внутри своего их нужно либо писать с ведущей косой чертой, либо импортировать: `use DateTime;`.

Со встроенными **функциями** проще: `strlen()`, `count()` находятся из любого неймспейса сами.

## Автозагрузка

Когда PHP встречает класс, которого ещё не знает, он не падает сразу, а вызывает зарегистрированную функцию-автозагрузчик и передаёт ей полное имя класса. Её задача — найти и подключить нужный файл.

```php
spl_autoload_register(function (string $class): void {
    // App\Models\User → src/Models/User.php
    $prefix = 'App\\';
    if (strncmp($class, $prefix, strlen($prefix)) !== 0) {
        return;                                    // чужой класс — не наше дело
    }

    $relative = substr($class, strlen($prefix));   // Models\User
    $path = __DIR__ . '/src/' . str_replace('\\', '/', $relative) . '.php';

    if (is_file($path)) {
        require $path;
    }
});
```

Это почти дословно автозагрузчик самой платформы — посмотри файл `src/bootstrap.php`.

В строке обратная косая черта экранируется: `'App\\'` — это текст `App\`.

## PSR-4

Чтобы автозагрузчик мог найти файл по имени класса, нужна договорённость. Она называется PSR-4:

- неймспейсу-префиксу соответствует папка: `App\` → `src/`;
- остальная часть имени повторяет путь: `App\Models\User` → `src/Models/User.php`;
- регистр букв совпадает.

Если класс «не найден», хотя файл на месте, почти всегда нарушено одно из трёх: не совпадает неймспейс в файле, имя файла или регистр. На Windows и macOS регистр прощается, на сервере с Linux — нет: «у меня работает, а на сервере нет».

## Composer

Писать автозагрузчик руками не нужно: это делает Composer, менеджер пакетов PHP. В файле `composer.json` указывается соответствие:

```json
{
    "autoload": {
        "psr-4": { "App\\": "src/" }
    }
}
```

После команды `composer dump-autoload` в проекте появляется файл `vendor/autoload.php`. Единственная строка, которая нужна в точке входа:

```php
require __DIR__ . '/vendor/autoload.php';
```

Она же подключает все установленные сторонние библиотеки.

## До автозагрузки: include и require

В легаси вместо автозагрузки — подключение файлов руками.

| Конструкция | Если файла нет | Повторное подключение |
|---|---|---|
| `include` | Предупреждение, код идёт дальше | Подключит снова |
| `require` | Фатальная ошибка | Подключит снова |
| `include_once`, `require_once` | То же | Пропустит |

Старые проекты начинаются с длинного списка `require_once`, порядок в котором важен. Забытая строка — «класс не найден», лишняя — «функция уже объявлена». Автозагрузка избавляет от этого целиком.

> **В PHP 7.** Неймспейсы, `use` и `spl_autoload_register` работают одинаково во всех версиях PHP 7 и 8. В заданиях этого урока несколько неймспейсов записаны в одном файле в фигурных скобках — `namespace App\Models { … }`. Так делают только в учебных примерах: в настоящем проекте каждый класс лежит в своём файле.
