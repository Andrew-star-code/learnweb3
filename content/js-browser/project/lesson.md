# Проект: список дел

Итог блока — маленькое, но настоящее приложение: список дел, который переживает перезагрузку страницы. В нём сходится всё: отрисовка из данных, делегирование событий, форма и хранилище.

Разметка и стили уже готовы. Твоя часть — скрипт.

## Что должно работать

**Добавление**

- Отправка формы `#new-todo` добавляет дело с текстом из поля `#todo-text`.
- Пробелы по краям текста убираются. Пустой текст ничего не добавляет.
- После добавления поле очищается.

**Список**

Каждое дело — элемент списка `#todos` такого вида:

```html
<li class="todo">
  <input type="checkbox">
  <span class="text">Купить зёрна</span>
  <button type="button" class="delete">×</button>
</li>
```

- У выполненного дела флажок отмечен, а у `li` есть класс `done`.
- Щелчок по флажку переключает «выполнено».
- Кнопка `.delete` удаляет дело.
- Текст дела вставляется как текст, а не как разметка.

**Счётчик**

- В элементе `#left` написано `Осталось: N`, где N — число невыполненных дел.

**Фильтр**

- Кнопки `.filter` с атрибутом `data-filter` — `all`, `active`, `done` — показывают все дела, только невыполненные или только выполненные.
- У выбранной кнопки класс `active`. Изначально выбрано «Все».
- Фильтр меняет только то, что показано. Сами дела и счётчик от него не зависят.

**Хранение**

- После каждого изменения список сохраняется в `localStorage` под ключом `todos` в виде JSON-массива объектов `{ text, done }`.
- Функция `load()` читает список из хранилища в состояние. Если там пусто или лежит мусор — получается пустой список.
- Функция `render()` рисует страницу по текущему состоянию.
- В конце скрипта вызываются `load()` и `render()` — так список восстанавливается при открытии страницы.

Тесты вызывают `load()` и `render()` по этим именам, поэтому объяви их обычными функциями на верхнем уровне скрипта.

## Как устроить код

Используй схему из прошлого урока:

```js
let todos = [];        // состояние: [{ text: '…', done: false }, …]
let filter = 'all';    // какой фильтр выбран

function load() { … }      // хранилище → todos
function save() { … }      // todos → хранилище
function render() { … }    // todos и filter → страница
```

Каждый обработчик делает одно и то же: **меняет состояние, вызывает `save()`, вызывает `render()`**. Напрямую элементы списка обработчики не трогают.

Один вопрос придётся решить самому: когда щёлкнули по флажку или кнопке удаления, как понять, какому элементу массива соответствует этот `<li>`? Простой способ — при отрисовке записать номер дела в атрибут `data-index`.

## Порядок работы

1. План — первое задание.
2. `render()` на заранее заполненном массиве: впиши в `todos` пару дел руками и добейся, чтобы они появились на странице.
3. Добавление через форму.
4. Переключение и удаление — одним обработчиком на списке.
5. Счётчик.
6. Фильтр.
7. `save()` и `load()`.

После каждого шага нажимай «Проверить»: тесты идут в том же порядке. Следи за панелью «Консоль» — ошибки скрипта появляются там.
