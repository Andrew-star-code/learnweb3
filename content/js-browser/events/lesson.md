# События и делегирование

Страница узнаёт о действиях человека через события: щелчок, нажатие клавиши, ввод текста, отправка формы. Скрипт заранее говорит браузеру: «когда на этом элементе случится такое событие — вызови эту функцию».

## Подписка

```js
const button = document.querySelector('.buy');

button.addEventListener('click', () => {
  console.log('нажали');
});
```

Второй аргумент — **функция**, а не её вызов. Очень частая ошибка:

```js
button.addEventListener('click', handleClick());   // вызовется сразу, один раз, при загрузке
button.addEventListener('click', handleClick);     // правильно: передаём саму функцию
```

Это та же разница между `action` и `action()`, что была в уроке про функции.

В старом коде встречаются атрибут `onclick="..."` в разметке и свойство `button.onclick = ...`. Они работают, но позволяют повесить только один обработчик и смешивают разметку с логикой.

## Частые события

| Событие | Когда происходит |
|---|---|
| `click` | Щелчок мышью, касание, нажатие Enter или пробела на кнопке |
| `input` | Значение поля изменилось — на каждый символ |
| `change` | Значение изменилось и поле потеряло фокус; для флажков и списков — сразу |
| `submit` | Отправка формы — событие **формы**, а не кнопки |
| `keydown` | Нажата клавиша |
| `focus`, `blur` | Элемент получил и потерял фокус |
| `DOMContentLoaded` | Страница разобрана, можно искать элементы |

## Объект события

Обработчик получает объект с подробностями.

```js
input.addEventListener('keydown', (event) => {
  if (event.key === 'Enter') {
    console.log('ввод завершён');
  }
});
```

| Свойство или метод | Что это |
|---|---|
| `event.target` | Элемент, на котором событие реально произошло |
| `event.currentTarget` | Элемент, на котором висит обработчик |
| `event.key` | Нажатая клавиша: `'Enter'`, `'Escape'`, `'a'` |
| `event.preventDefault()` | Отменить стандартное действие браузера |

`preventDefault` нужен, когда у события есть действие по умолчанию, а ты хочешь сделать своё: ссылка не должна уводить со страницы, форма не должна перезагружать её.

## Всплытие

Событие не остаётся на элементе: оно поднимается вверх по дереву — к родителю, его родителю и так до `document`. Щелчок по кнопке внутри карточки — это ещё и щелчок по карточке, и по списку, и по странице.

Поэтому `target` и `currentTarget` могут не совпадать: обработчик висит на списке (`currentTarget`), а щёлкнули по кнопке внутри него (`target`).

## Делегирование

Из всплытия следует важный приём. Вместо обработчика на каждом элементе списка ставят **один обработчик на общего родителя** и внутри выясняют, по чему щёлкнули.

```js
list.addEventListener('click', (event) => {
  const button = event.target.closest('.delete');   // щёлкнули по кнопке удаления или внутри неё?
  if (!button) return;                              // нет — это не наш случай

  button.closest('li').remove();
});
```

`closest(selector)` ищет ближайшего предка, подходящего под селектор, начиная с самого элемента. Он нужен потому, что щёлкнуть могут не по самой кнопке, а по иконке внутри неё.

Чем делегирование лучше:

- **Работает для элементов, которых ещё нет.** Пункт, добавленный в список позже, обрабатывается без единой лишней строчки. С отдельными обработчиками про новые элементы легко забыть — и это типичный баг: «старые кнопки работают, новые нет».
- Один обработчик вместо сотни.

Если элементы появляются и исчезают — список дел, таблица, корзина — делегирование почти всегда правильный выбор.

## Состояние в классах

Типичный обработчик не рисует что-то сам, а переключает состояние, которое описано в CSS:

```js
toggle.addEventListener('click', () => {
  const open = menu.classList.toggle('open');          // toggle возвращает новое состояние
  toggle.setAttribute('aria-expanded', String(open));  // сообщаем его программам экранного доступа
});
```
