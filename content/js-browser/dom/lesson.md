# DOM: страница как дерево объектов

Когда браузер читает HTML, он строит из него дерево объектов — DOM. Каждый тег становится объектом со свойствами и методами. JavaScript меняет эти объекты, а браузер тут же перерисовывает страницу. Вся интерактивность в вебе сводится к трём действиям: **найти элемент, прочитать его, изменить его**.

## Найти

```js
const title = document.querySelector('.title');      // первый подходящий или null
const items = document.querySelectorAll('.item');    // все подходящие
```

Оба метода принимают селектор CSS — те самые, что ты писал в стилях.

Два отличия, о которые спотыкаются постоянно:

- `querySelector` возвращает **один элемент** или `null`, если ничего не нашлось. Обращение к свойству у `null` — это `TypeError`, самая частая ошибка в браузерном коде.
- `querySelectorAll` возвращает **коллекцию**, даже если в ней один элемент. У коллекции нет `textContent` и `classList` — её нужно перебирать: `items.forEach(...)` или `for...of`.

Искать можно и внутри элемента: `card.querySelector('.price')`.

## Прочитать и изменить содержимое

```js
title.textContent = 'Новый заголовок';     // текст
box.innerHTML = '<b>жирный</b> текст';     // HTML-разметка
```

**`textContent` — выбор по умолчанию.** Он вставляет строку как текст: теги в ней покажутся буквами и ничего не сломают.

`innerHTML` разбирает строку как разметку. Если в неё попадут данные от пользователя — имя, комментарий, параметр из адреса — в них может оказаться чужой скрипт, и он выполнится на твоей странице. Это уязвимость XSS, одна из самых распространённых в вебе. Правило: **в `innerHTML` никогда не попадает то, что ввёл человек**.

## Классы, атрибуты, стили

```js
card.classList.add('active');
card.classList.remove('active');
card.classList.toggle('open');          // есть — убрать, нет — добавить
card.classList.contains('open');        // true или false

link.getAttribute('href');
link.setAttribute('href', '/new');
input.value;                            // у полей формы — готовые свойства
button.disabled = true;
panel.hidden = true;                    // скрыть элемент

card.dataset.id;                        // атрибут data-id="42" → '42'
```

Менять внешний вид лучше **переключением классов**, а не записью в `element.style`. Оформление остаётся в CSS, а скрипт только сообщает состояние: «открыто», «выбрано», «ошибка».

Атрибуты `data-*` — способ хранить в разметке данные для скрипта: идентификатор товара, цену. Значение всегда строка.

## Создать и удалить

```js
const li = document.createElement('li');   // создать
li.textContent = 'Новый пункт';            // наполнить
li.classList.add('item');
list.append(li);                           // вставить в конец списка

li.remove();                               // удалить
list.replaceChildren();                    // убрать всё содержимое
```

Созданный элемент не виден, пока его не вставили в документ. Кроме `append` есть `prepend` (в начало), `before` и `after` (рядом с элементом).

## Отрисовка из данных

Самый полезный приём: данные лежат в массиве, а функция превращает их в элементы страницы.

```js
function renderList(list, names) {
  list.replaceChildren();                  // очистить
  for (const name of names) {
    const li = document.createElement('li');
    li.textContent = name;
    list.append(li);
  }
}
```

Это «преобразование» из первых уроков: был массив строк, стал набор элементов. На таком приёме построены все списки, таблицы и каталоги, которые приходят с сервера.

## Когда запускается скрипт

Браузер читает страницу сверху вниз. Скрипт, который стоит выше элемента, этого элемента ещё не видит: `querySelector` вернёт `null`.

Три способа это решить:

```html
<body>
  …разметка…
  <script src="app.js"></script>           <!-- 1. скрипт в конце body -->
</body>
```

```html
<script src="app.js" defer></script>       <!-- 2. defer: выполнить после разбора страницы -->
```

```js
document.addEventListener('DOMContentLoaded', () => {   // 3. дождаться события
  // страница готова
});
```

В новом коде обычно пишут `defer` в `<head>`. В заданиях скрипт лежит в теге `<script>` после разметки.

> **Консоль в заданиях.** Под предпросмотром появляется панель «Консоль»: туда попадает всё, что ты вывел через `console.log`, и ошибки скрипта с номером строки. Это твой главный инструмент отладки в этом блоке — в обычной работе его роль играет вкладка Console в инструментах браузера (F12).
