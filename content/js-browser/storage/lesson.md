# localStorage

Переменные скрипта живут до перезагрузки страницы. Чтобы данные пережили её — выбранная тема, черновик письма, корзина — их нужно куда-то записать. Самое простое место в браузере — `localStorage`.

## Четыре метода

```js
localStorage.setItem('theme', 'dark');     // записать
localStorage.getItem('theme');             // прочитать: 'dark'
localStorage.getItem('nope');              // такого ключа нет: null
localStorage.removeItem('theme');          // удалить один ключ
localStorage.clear();                      // удалить всё
```

Данные хранятся отдельно для каждого сайта, остаются после закрытия браузера и не имеют срока годности.

## Хранятся только строки

Это главное, что нужно помнить. Всё, что ты записываешь, превращается в строку:

```js
localStorage.setItem('count', 5);
localStorage.getItem('count');             // '5' — строка
localStorage.getItem('count') + 1;         // '51'

localStorage.setItem('items', ['чай', 'кофе']);
localStorage.getItem('items');             // 'чай,кофе' — массива больше нет

localStorage.setItem('user', { name: 'Аня' });
localStorage.getItem('user');              // '[object Object]' — данные потеряны
```

Поэтому массивы и объекты сохраняют через JSON:

```js
localStorage.setItem('items', JSON.stringify(items));     // записать
const items = JSON.parse(localStorage.getItem('items'));  // прочитать
```

## Чтение, которое не падает

У чтения есть два особых случая, и оба встречаются в жизни.

**Первый визит.** Ключа ещё нет, `getItem` возвращает `null`. `JSON.parse(null)` тоже даёт `null`, и первый же `items.push(...)` падает с `TypeError`.

**Испорченные данные.** В хранилище может лежать что угодно: значение от старой версии сайта, обрезанная строка, правка руками. `JSON.parse` на таком бросает ошибку — и если её не перехватить, сайт у этого человека не откроется вообще, пока он не очистит хранилище.

Надёжное чтение учитывает оба случая:

```js
function loadItems() {
  try {
    return JSON.parse(localStorage.getItem('items')) ?? [];
  } catch (error) {
    return [];
  }
}
```

Это тот случай из урока про ошибки, когда перехват уместен: мы точно знаем, что делать, — начать с пустого списка.

## Состояние, сохранение, отрисовка

Когда данных на странице становится больше одного значения, выручает простая схема из трёх частей.

```js
let items = loadItems();              // 1. состояние: единственный источник правды

function save() {                     // 2. сохранение
  localStorage.setItem('items', JSON.stringify(items));
}

function render() {                   // 3. отрисовка: строит страницу из состояния
  list.replaceChildren();
  for (const item of items) { /* … */ }
}

function addItem(text) {              // любое изменение идёт одним путём:
  items.push(text);                   //   изменить состояние
  save();                             //   сохранить
  render();                           //   перерисовать
}
```

Ключевая идея: **страница — это отражение данных, а не их хранилище**. Обработчики событий не правят элементы по одному, а меняют массив и вызывают `render()`. Тогда страница не может разойтись с данными, а восстановление после перезагрузки получается само: загрузил состояние, вызвал `render()`.

На этой схеме построен проект в конце блока — и, в усложнённом виде, все современные фреймворки.

## Что не стоит хранить

- **Пароли, токены доступа, платёжные данные.** `localStorage` читается любым скриптом на странице, включая чужой, если на сайте есть XSS-уязвимость.
- **Большие объёмы.** Лимит — около 5 МБ на сайт.
- **Данные, которые нужны серверу.** Сервер `localStorage` не видит. Для этого есть cookies — о них в блоке про PHP.

Рядом есть `sessionStorage` с теми же методами: он хранит данные, пока открыта вкладка.

> **В заданиях** у каждого задания своё хранилище, оно сохраняется между перезапусками предпросмотра. Кнопка «Очистить хранилище» под редактором возвращает состояние «первого визита». Тесты всегда начинают с пустого хранилища.
