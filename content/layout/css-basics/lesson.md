# Каскад и селекторы

CSS — это список правил вида «для таких-то элементов сделай так-то».

```css
.card h2 {            /* селектор: кого касается */
  color: darkgreen;   /* объявление: свойство и значение */
  font-size: 20px;
}
```

В заданиях стили лежат в теге `<style>` рядом с разметкой. В настоящих проектах их выносят в отдельный файл и подключают в `<head>`: `<link rel="stylesheet" href="style.css">`.

## Селекторы

| Селектор | Кого выбирает |
|---|---|
| `p` | Все теги `p` |
| `.note` | Элементы с классом `note` |
| `#header` | Элемент с `id="header"` |
| `.card p` | `p` где угодно внутри `.card` |
| `.card > p` | `p`, лежащие прямо в `.card`, без промежуточных тегов |
| `h1, h2` | И `h1`, и `h2` |
| `a.active` | Ссылки, у которых есть класс `active` |
| `input[type="email"]` | По значению атрибута |

Псевдоклассы уточняют состояние или положение элемента:

| Селектор | Кого выбирает |
|---|---|
| `a:hover` | Ссылку под курсором |
| `input:focus` | Поле, в котором стоит курсор |
| `li:first-child`, `li:last-child` | Первый и последний среди соседей |
| `li:nth-child(even)` | Чётные по счёту (`odd` — нечётные) |
| `li:not(.done)` | Все, кроме имеющих класс `done` |

Рабочее правило: **стилизуй по классам**. Классы можно переиспользовать, они не привязаны к конкретному тегу и не создают проблем с приоритетом.

## Каскад: какое правило победит

Когда одному элементу одно и то же свойство задают несколько правил, браузер выбирает победителя в три шага.

**1. Специфичность селектора.** Чем точнее селектор, тем он сильнее:

```text
#id   >   .класс, :псевдокласс, [атрибут]   >   тег
```

Считается количество: один `id` сильнее любого числа классов, один класс сильнее любого числа тегов. `.card .title` (два класса) сильнее, чем `.title` (один).

**2. Порядок.** При равной специфичности побеждает правило, которое написано ниже.

**3. `!important`** перебивает всё. Это аварийный выход: правило с ним потом можно перебить только другим `!important`, и стили превращаются в гонку вооружений. В своём коде его почти всегда можно избежать.

Отсюда практический совет: не используй `#id` в селекторах. Правило с `id` потом не перебить классом, и приходится громоздить всё более длинные селекторы.

## Наследование

Свойства текста — `color`, `font-family`, `font-size`, `line-height` — передаются от родителя к потомкам. Поэтому шрифт задают один раз для `body`.

Свойства блока — отступы, рамки, фон, размеры — не наследуются.

## Единицы и цвета

| Единица | Что значит |
|---|---|
| `px` | Пиксели. Для рамок, теней, мелких деталей |
| `rem` | Размер шрифта корневого элемента, обычно 16px. Для шрифтов и отступов: всё масштабируется вместе с настройками пользователя |
| `em` | Размер шрифта самого элемента |
| `%` | Доля от родителя |

Цвета: по имени (`white`), шестнадцатеричный код (`#2f6f4f`), `rgb(47, 111, 79)`, с прозрачностью — `rgb(47 111 79 / 50%)`.

## Переменные

Значение, которое повторяется по всему сайту, объявляют один раз:

```css
:root {
  --accent: #2f6f4f;
  --gap: 16px;
}

.button { background: var(--accent); }
.title  { color: var(--accent); }
```

Имя переменной начинается с двух дефисов. Объявленная в `:root`, она доступна на всей странице. Поменял в одном месте — изменилось везде. Так устроены темы, в том числе в Bootstrap 5.
