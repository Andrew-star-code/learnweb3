# Что появилось в какой версии

В блоке «Ядро PHP» ты писал на PHP 8. На работе тебя ждёт код, который крутится на PHP 7.0–7.3, и это меняет две вещи. Половины привычных конструкций там нет. А то, что есть, местами ведёт себя иначе.

Этот блок — про жизнь между версиями. Писать новое в старом стиле не придётся: цель — уверенно читать старый код, вносить в него небольшие правки и не сломать при этом сервер.

## Как устроены версии

Номер состоит из трёх чисел: `7.0.33` — основная версия, минорная, исправления. Новые возможности языка появляются в минорных версиях (7.1, 7.4, 8.1), а третье число — только починки.

Узнать версию:

```php versions
echo PHP_VERSION, "\n";       // строка: 8.3.6
echo PHP_VERSION_ID, "\n";    // число: 80306 — удобно сравнивать
echo PHP_MAJOR_VERSION, '.', PHP_MINOR_VERSION, "\n";
```

Кнопка под примером выполняет его сразу на двух версиях — в этом блоке она будет встречаться часто. В консоли то же самое показывает команда `php -v`. Версия на рабочем сервере и версия в консоли на твоей машине могут не совпадать: проверяй там, где код будет выполняться.

Обычным сравнением версии сравнивать нельзя: PHP увидит в `'7.10'` и `'7.4'` дробные числа, а 7.1 меньше 7.4. Для версий есть `version_compare`:

```php versions
var_dump('7.10' >= '7.4');                          // false — сравнились как дробные числа 7.1 и 7.4
var_dump(version_compare('7.10', '7.4', '>='));     // true — сравнились по частям
var_dump(version_compare(PHP_VERSION, '7.4.0', '>='));
var_dump(PHP_VERSION_ID >= 70400);                  // то же через число
```

## Таблица: что когда появилось

Запоминать её целиком не нужно. Нужно знать, что она существует, и помнить две границы: **7.0** — самая старая версия, с которой ты встретишься, и **8.0** — версия, в которой появилось больше всего нового.

| Версия | Что появилось |
|---|---|
| **7.0** | Типы `int`, `float`, `string`, `bool` у параметров; тип результата; `declare(strict_types=1)`; `??`; `<=>`; `Throwable` и класс `Error`; `intdiv`, `random_int` |
| **7.1** | Nullable-типы `?int`; `void`; короткая запись `[$a, $b] = $pair`; несколько классов в одном `catch (A \| B $e)`; `private const` |
| **7.2** | Тип `object`; `count()` для не-массива начинает предупреждать |
| **7.3** | Запятая после последнего аргумента при вызове; `array_key_first`, `array_key_last`; `JSON_THROW_ON_ERROR`; `is_countable` |
| **7.4** | Типы свойств `private int $x`; стрелочные функции `fn($x) => …`; `??=`; распаковка в массиве `[...$a, ...$b]`; `1_000_000` |
| **8.0** | Именованные аргументы; продвижение свойств в конструкторе; `match`; `?->`; объединения типов `int\|string`; `mixed`; `str_contains`, `str_starts_with`, `str_ends_with`; `throw` как выражение |
| **8.1** | `enum`; `readonly`-свойства; `never`; `strlen(...)` как ссылка на функцию; `array_is_list` |
| **8.2** | `readonly`-классы; динамические свойства объявлены устаревшими |
| **8.3** | Типы у констант класса; `json_validate`; атрибут `#[\Override]` |

Из таблицы следует неприятный вывод: на сервере с PHP 7.0 нет почти ничего из того, чем ты пользовался в прошлом блоке. Нет `?int` и `void`, нет типов у свойств, нет стрелочных функций, `match`, `enum`, `str_contains`.

Зато всё, что есть в 7.0, работает и в 8.3. Код, написанный в расчёте на старую версию, запустится на новой — с оговорками, которым посвящён следующий урок.

## Два вида «нового»: синтаксис и функции

Это главное различие урока. От него зависит, как код сломается и как его чинить.

**Новый синтаксис** PHP 7.0 не может даже прочитать. Файл разбирается целиком до начала выполнения, поэтому одна незнакомая конструкция в любом месте — и не выполнится ни одна строка:

```php versions
echo "Начало\n";

function label(?string $name): string     // ?string — это PHP 7.1
{
    return $name ?? 'Гость';
}

echo "Функцию даже не вызывали\n";
```

В PHP 7.0 не появится даже слово «Начало»: ошибка разбора (`Parse error`) возникает раньше, чем начинается выполнение. Сообщение обычно выглядит как `syntax error, unexpected '?'` — PHP называет символ, на котором споткнулся, и номер строки.

**Новая функция** — другое дело. Вызов `str_contains(…)` синтаксически ничем не отличается от вызова любой другой функции, поэтому файл разбирается. Ошибка возникнет, только когда выполнение дойдёт до этой строки:

```php versions
echo "Начало\n";

if (str_contains('капучино', 'чин')) {
    echo "Нашлось\n";
}
```

Здесь «Начало» выведется на обеих версиях, а потом PHP 7.0 упадёт с `Call to undefined function str_contains()`.

| | Новый синтаксис | Новая функция |
|---|---|---|
| Когда ломается | При разборе файла, до выполнения | Когда дошло до вызова |
| Сообщение | `Parse error: syntax error, unexpected …` | `Call to undefined function …` |
| Что пострадает | Весь файл | Только эта ветка кода |
| Можно ли добавить в старую версию | Нет, только переписать | Да — написать функцию самому |

Вторая строка таблицы опаснее, чем кажется. Синтаксическую ошибку ты увидишь при первом же открытии страницы. Вызов отсутствующей функции в редкой ветке — например, в обработке ошибки оплаты — может пролежать на сервере месяц.

## Полифил: функция из будущего

Раз функция — это просто функция, недостающую можно объявить самому. Такую заплатку называют полифилом:

```php
if (!function_exists('str_contains')) {
    function str_contains($haystack, $needle)
    {
        return $needle === '' || strpos($haystack, $needle) !== false;
    }
}
```

Проверка `function_exists` обязательна. Без неё тот же файл на PHP 8 упадёт: объявить функцию с именем уже существующей нельзя. С проверкой код одинаково работает на обеих версиях, а после обновления сервера полифил просто перестанет использоваться.

В больших проектах полифилы не пишут руками, а подключают готовые пакеты `symfony/polyfill-php80`, `symfony/polyfill-php81`. Если видишь такие в `composer.json` — теперь понятно, зачем они.

## Как понять, на что рассчитан код

- В `composer.json` в разделе `require` есть строка вида `"php": ">=7.0"` или `"^7.2"`. Это обещание автора, а не гарантия.
- По самому коду: встретился `fn` — значит, не ниже 7.4; `match` или `?->` — не ниже 8.0.
- Проверить файл, не выполняя его: `php -l файл.php`. Команда только разбирает синтаксис — и делать это нужно интерпретатором **той версии, что на сервере**.

> **Правило правки.** Прежде чем писать в чужом проекте, узнай версию PHP на сервере. Она определяет, какими конструкциями можно пользоваться. Дописать в старый файл стрелочную функцию «как привык» — самый частый способ положить сайт на PHP 7.
