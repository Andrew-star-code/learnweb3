# Что молча изменилось в PHP 8

Ошибка разбора — громкая: страница не открывается, причина написана в первой строке журнала. Гораздо неприятнее код, который выполняется на обеих версиях, но **даёт разный результат**. Никто ничего не менял, сервер обновили — и в отчёте другие суммы.

В этом уроке — такие изменения. Почти каждый пример можно запустить на двух версиях сразу и сравнить колонки. Делай это: увиденная своими глазами разница запоминается лучше таблицы.

## Сравнение числа со строкой

Самое известное изменение. Оператор `==` при сравнении числа со строкой должен привести их к одному типу.

- **PHP 7** превращал строку в число. Строка без цифр становилась нулём, поэтому `0 == 'кофе'` — истина.
- **PHP 8** сначала смотрит на строку. Если она похожа на число, сравнивает числа. Если нет — превращает число в строку и сравнивает строки: `'0'` и `'кофе'` не равны.

```php versions
var_dump(0 == 'кофе');
var_dump(0 == '');
var_dump(42 == '42 руб');
var_dump('1' == '01');      // обе строки числовые — здесь ничего не менялось
var_dump(null == false);    // и здесь
```

Сам по себе `==` в коде хотя бы виден. Хуже, что нестрогое сравнение спрятано внутри `in_array`, `array_search` и `switch`:

```php versions
var_dump(in_array('латте', [0, 1, 2]));

function discount($code)
{
    switch ($code) {
        case 0:
            return 'без скидки';
        case 'VIP':
            return 'скидка 20%';
        default:
            return 'неизвестный код';
    }
}

echo discount('VIP'), "\n";
```

В PHP 7 функция `discount` годами отвечала «без скидки» на любой текстовый код: `'VIP' == 0` было истиной, и до второй ветки дело не доходило. PHP 8 эту ошибку «исправил» — и магазин внезапно начал давать скидки. Новое поведение правильнее, но это всё равно изменение, о котором никто не просил.

Лечение одно на обе версии — не давать PHP выбирать:

- `===` вместо `==`;
- `in_array($value, $list, true)` и `array_search($value, $list, true)` — третий аргумент включает строгое сравнение;
- перед `switch` привести значение к нужному типу или сравнивать в `case` значения того же типа.

## Было предупреждение — стало исключение

PHP 7 был снисходителен к бессмысленным операциям: выдавал предупреждение (или вообще молчал), подставлял что-нибудь и шёл дальше. PHP 8 в тех же местах бросает исключение, и если его никто не ловит, скрипт останавливается.

| Код | PHP 7.0 | PHP 8 |
|---|---|---|
| `100 * 'две'` | `0`, молча | `TypeError` |
| `100 * ''` | `0`, молча | `TypeError` |
| `10 / 0` | предупреждение, результат `INF` | `DivisionByZeroError` |
| `count(null)` | `0`, молча | `TypeError` |
| `count('текст')` | `1`, молча | `TypeError` |
| `strlen([])` | предупреждение, результат `null` | `TypeError` |
| `'текст'['ключ']` | предупреждение, первый символ | `TypeError` |

Типичный сценарий — пустое поле формы. Всё, что приходит из формы, — строки, и незаполненное количество — это `''`:

```php versions
$row = ['price' => 250, 'qty' => ''];

echo $row['price'] * $row['qty'], "\n";
echo "Скрипт дошёл до конца\n";
```

В PHP 7 строка заказа получала сумму 0, и этого никто не замечал. В PHP 8 страница падает. И снова: новое поведение честнее, но для пользователя «раньше работало, а теперь ошибка 500».

То же с пустым списком и делением:

```php versions
$ratings = [];

echo array_sum($ratings) / count($ratings), "\n";
echo "Скрипт дошёл до конца\n";
```

## Было замечание — стало предупреждение

Чтение того, чего нет, — переменной, ключа массива, свойства — не останавливает скрипт ни в одной версии: получается `null`. Изменились уровень и текст сообщения.

```php versions
$user = ['name' => 'Аня'];

echo 'Город: ', $user['city'], "\n";
echo 'Длина: ', strlen($user['city']), "\n";
```

| | PHP 7.0 | PHP 8 |
|---|---|---|
| Нет переменной | `Notice: Undefined variable: x` | `Warning: Undefined variable $x` |
| Нет ключа | `Notice: Undefined index: city` | `Warning: Undefined array key "city"` |
| `null` в строковой функции | молча | `Deprecated` начиная с 8.1 |

Почему это важно, если скрипт всё равно работает:

- На многих старых серверах замечания (`Notice`) отключены в настройках, а предупреждения — нет. После обновления журнал ошибок вырастает в сотни раз.
- В проекте может стоять обработчик, который превращает предупреждения в исключения. Тогда «всего лишь предупреждение» роняет страницу.
- Если искать ошибку в журнале по старому тексту `Undefined index`, в PHP 8 ничего не найдётся.

`Deprecated` означает «пока работает, но в следующей основной версии перестанет». Это не шум, а список будущих поломок.

## Порядок действий

В PHP 7 сложение и склейка строк имели одинаковый приоритет и выполнялись слева направо. В PHP 8 сложение выполняется раньше склейки.

```php versions
$price = 250;
$delivery = 100;

echo 'Итого: ' . $price + $delivery, "\n";
```

PHP 7 сначала склеивал `'Итого: 250'`, потом пытался прибавить к этой строке 100 — строка превращалась в ноль, и на экране оставалось `100` без подписи. PHP 8 считает так, как автор и хотел. Скобки убирают разницу: `'Итого: ' . ($price + $delivery)`.

Вложенный тернарный оператор без скобок — `$a ? 1 : $b ? 2 : 3` — PHP 7 вычислял слева направо, чаще всего не так, как ожидал автор. PHP 8 такой код отказывается разбирать вовсе и требует расставить скобки.

## Функции, которые отвечают иначе

| Вызов | PHP 7.0 | PHP 8 |
|---|---|---|
| `substr('abc', 5)` | `false` | `''` |
| `strpos('abc', '')` | предупреждение, `false` | `0` |
| `implode($list, ', ')` — старый порядок аргументов | работает | `TypeError` |
| `usort` с функцией, возвращающей `true`/`false` | работает | `Deprecated` |
| Сортировка массива, где смешаны числа и текст | один порядок | другой порядок |

Проверка `if (substr($code, 3) === false)` в PHP 8 никогда не сработает. Функция сравнения для `usort` должна возвращать число — проще всего через `<=>`, он есть уже в 7.0.

## Что удалили совсем

Это уже громкие поломки, но встретишь ты их в том же проекте: `each()`, `create_function()`, обращение к символу строки через фигурные скобки `$text{0}`, функция `__autoload`. Вызов любой из них в PHP 8 — фатальная ошибка. К ним вернёмся в уроке про чтение легаси.

## Как с этим жить

У всех изменений из этого урока есть общее свойство: **в PHP 7 такие места почти всегда оставляли след** — замечание или предупреждение в журнале. Отсюда рабочий порядок действий перед обновлением:

1. На старой версии включить показ всех ошибок: `error_reporting(E_ALL)` — и собрать журнал.
2. Каждое сообщение в нём — кандидат на падение или смену поведения. Исправить причину, а не заглушить.
3. Прогнать код на обеих версиях и сравнить результат.

А для своих правок — писать так, чтобы от версии ничего не зависело:

| Вместо | Пиши |
|---|---|
| `$a == $b` | `$a === $b`, предварительно приведя типы |
| `in_array($x, $list)` | `in_array($x, $list, true)` |
| `$price * $qty` для данных из формы | проверить `is_numeric`, привести `(int)` или `(float)` |
| `$sum / $count` | сначала проверить, что `$count` не ноль |
| `$row['key']`, когда ключа может не быть | `$row['key'] ?? значение` |
| `'текст' . $a + $b` | `'текст' . ($a + $b)` |

> **В PHP 7.1–7.3** часть таблицы «было — стало» выглядит мягче, чем в 7.0: арифметика с нечисловой строкой уже даёт предупреждение `A non-numeric value encountered` (с 7.1), а `count()` от не-массива — предупреждение с 7.2. Результат при этом прежний. На таких версиях журнал подскажет больше проблемных мест, чем на 7.0.
