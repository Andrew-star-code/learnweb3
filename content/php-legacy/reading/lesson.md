# Чтение и правка легаси

Легаси — это код, который давно работает и приносит деньги, но написан другими людьми, в другое время и по другим правилам. Его не переписывают «как надо»: на это нет ни времени, ни тестов, которые подтвердили бы, что новая версия делает то же самое.

Твоя обычная задача в таком проекте — небольшая: добавить поле, поправить расчёт, закрыть дыру. Для неё нужны два умения: **прочитать** чужой код ровно настолько, чтобы понять нужное место, и **изменить** его так, чтобы не задеть ничего вокруг.

## Как выглядит типичная страница

```php
<?php
include 'config.php';
include 'functions.php';

$status = $_GET['status'];
$sql = "SELECT * FROM orders WHERE status = '" . $status . "' ORDER BY id DESC";
$result = mysqli_query($db, $sql) or die('Ошибка базы');
?>
<h1>Заказы</h1>
<table>
<?php while ($row = mysqli_fetch_assoc($result)) { ?>
    <tr>
        <td><?= $row['customer'] ?></td>
        <td><?php echo $row['total'] * (1 + $tax / 100); ?> руб.</td>
    </tr>
<?php } ?>
</table>
```

В пятнадцати строках — почти всё, с чем придётся иметь дело:

- `$db` и `$tax` нигде не объявлены. Они пришли из подключённых файлов.
- Запрос к базе склеен из того, что прислал пользователь.
- Имя клиента выводится в страницу как есть.
- Расчёт суммы с налогом стоит прямо в разметке.
- `or die(…)` — вся обработка ошибок.

Разберём по порядку.

## Откуда взялась переменная

`include` и `require` работают как вставка текста: содержимое файла выполняется прямо в этом месте. Все переменные подключённого файла становятся видны здесь, а все здешние — там. Поэтому первый вопрос к любой незнакомой переменной: **в каком файле ей присвоили значение?**

- Поиск по проекту: не `$tax`, а `$tax =` — так находятся присваивания, а не все упоминания.
- `var_dump(get_included_files());` — список всех файлов, подключённых к этому моменту.
- `var_dump(array_keys(get_defined_vars()));` — имена всех переменных, которые сейчас существуют.

С функциями наоборот. В JavaScript функция видит переменные снаружи. В PHP — **нет**:

```php versions
$taxRate = 20;

function withTax($price)
{
    return $price + $price * $taxRate / 100;
}

echo withTax(100), "\n";
```

Внутри функции `$taxRate` — другая, пустая переменная. Получается замечание и цена без налога. Чтобы дотянуться до внешней переменной, в старом коде пишут `global`:

```php
function withTax($price)
{
    global $taxRate;

    return $price + $price * $taxRate / 100;
}
```

`global` — главный источник сюрпризов в легаси. По сигнатуре `withTax($price)` не видно, что результат зависит от чего-то ещё. И любая функция может глобальную переменную не только прочитать, но и изменить — тогда поведение начинает зависеть от того, что вызывали раньше.

Есть и способы создать переменную так, что поиск по имени её не найдёт:

```php
extract($row);              // из ключей массива делает переменные: $id, $customer, $total…
$$field = $value;           // имя переменной лежит в другой переменной
```

Увидел `extract` выше по файлу — значит, «необъявленные» переменные ниже могут быть ключами этого массива.

## Признаки возраста

| Что видишь | Что это значит |
|---|---|
| `array(1, 2)` | Старая запись массива. Работает во всех версиях — не трогать |
| `mysql_query(…)` | Расширение `mysql` удалено ещё в PHP 7.0. На сервере с 7.x его заменяют `mysqli_*` или PDO |
| `@функция(…)`, `or die(…)` | Ошибки заглушены. Если что-то «просто не работает» — убери `@` на время поиска |
| `global $db;` | Зависимость функции не видна в сигнатуре |
| `extract(…)`, `$$name` | Переменные появляются из ниоткуда |
| `<? … ?>` без слова `php` | Короткий тег. Работает, только если включён в настройках сервера |
| `each()`, `create_function()`, `$text{0}` | Удалено в PHP 8. Пока сервер на 7 — работает |
| `?>` в конце файла с одним PHP | Пробел или пустая строка после него уйдут в ответ и сломают отправку заголовков |

## Две дыры, которые нужно узнавать в лицо

Им посвящён отдельный блок курса. Но встречаются они в каждом втором старом файле, поэтому узнавать их нужно уже сейчас.

**Склейка запроса.** Значение из адресной строки подставляется прямо в текст SQL:

```php
$sql = "SELECT * FROM orders WHERE status = '" . $_GET['status'] . "'";
```

Если вместо статуса прислать `' OR '1'='1`, запрос вернёт все заказы. Этот текст стал частью запроса, а не значением.

Правильное лечение — запрос с местами для значений, а сами значения отдельным списком. Так они никогда не смешиваются с текстом запроса:

```php
$sql = 'SELECT * FROM orders WHERE status = ?';
$params = array($_GET['status']);
```

Как передать такую пару базе данных, разберём в блоке про базы. Минимальная правка, когда значение должно быть целым числом, — привести тип: `(int) $_GET['id']`. Из числа запрос не составить.

**Вывод без экранирования.** Имя клиента `<script>…</script>` выполнится в браузере каждого, кто откроет страницу. Всё, что попадает в HTML из базы или от пользователя, проходит через `htmlspecialchars`:

```php versions
$name = "<b>О'Брайен</b>";

echo htmlspecialchars($name), "\n";
echo htmlspecialchars($name, ENT_QUOTES, 'UTF-8'), "\n";
```

Сравни первую строку в двух колонках: до PHP 8.1 функция по умолчанию не трогала одинарную кавычку. Ещё одно молчаливое изменение — и причина всегда писать второй и третий аргументы явно.

## Правило минимальной правки

1. **Воспроизвести.** Открыть страницу, увидеть ошибку или место для новой возможности своими глазами.
2. **Зафиксировать, как работает сейчас.** Тестов в легаси обычно нет, поэтому сохрани вывод страницы до правки. Это твой тест: после правки отличаться должно только то, что ты менял.
3. **Найти наименьшее изменение.** Не «как бы я написал это заново», а «какую одну строку нужно поменять».
4. **Не трогать остальное.** Не переформатировать, не переименовывать, не менять `array()` на `[]`, не исправлять соседние странности. В списке изменений должна быть видна твоя правка, а не восемьсот строк, среди которых она спрятана.
5. **Писать в стиле файла и под версию сервера.** Стрелочная функция в файле для PHP 7.0 — это не «современнее», это ошибка разбора.
6. **Проверить на версии сервера** и сравнить вывод с сохранённым.

Заметил по дороге другую ошибку — запиши и сообщи. Это отдельная задача и отдельная правка.

> Старый код некрасив, но за годы он оброс исправлениями для случаев, о которых ты не знаешь. Странная проверка посреди функции — возможно, след реальной аварии. Не удаляй то, назначение чего не понял.

## Вынести логику из разметки

Самый полезный приём, когда править всё-таки нужно расчёт. Вычисление, вросшее в HTML, нельзя ни проверить, ни использовать в другом месте. Его выносят в функцию в три шага:

1. Найти, какие переменные расчёт **читает** — это будущие параметры.
2. Найти, какие переменные он **создаёт** для разметки ниже — это будущий результат.
3. Перенести строки в функцию, а в разметке оставить вызов.

Было — расчёт в середине таблицы:

```php
<?php
    $price = $row['total'] * (1 + $tax / 100);
    $label = $price > 1000 ? 'крупный' : '';
?>
```

Стало — функция вверху файла или в `functions.php`:

```php
function orderView(array $row, $tax)
{
    $price = $row['total'] * (1 + $tax / 100);

    return array(
        'price' => $price,
        'label' => $price > 1000 ? 'крупный' : '',
    );
}
```

И вызов на прежнем месте:

```php
<?php $view = orderView($row, $tax); ?>
```

Обрати внимание: `$tax` стал параметром, а не `global`. Страница при этом выводит ровно то же, что раньше, — а у функции теперь можно проверить любой случай, не открывая браузер.
