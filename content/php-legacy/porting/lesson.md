# Перенос кода между версиями

Код переносят в обе стороны. **Вниз** — когда нужную функцию ты нашёл в новом проекте, в документации или получил от нейросети, а вставить её надо в проект на PHP 7.0. **Вверх** — когда старый проект наконец обновляют и код можно осовременить.

Вниз переносить приходится чаще, и ошибиться там проще: всё, что ты пишешь по привычке, на старом сервере не разберётся.

## Вниз: таблица замен

Слева — как в PHP 8, справа — то же самое средствами PHP 7.0.

| PHP 8 | PHP 7.0 |
|---|---|
| `fn($x) => $x * $k` | `function ($x) use ($k) { return $x * $k; }` |
| `match ($x) { … }` | `switch` или массив-справочник |
| `$a?->b()` | `$a !== null ? $a->b() : null` |
| `?int $x` у параметра | `int $x = null` |
| `: ?int`, `: void`, `int\|string`, `mixed` | убрать, описать в комментарии `@return` |
| `private int $x;` | `private $x;` и комментарий `@var int` |
| продвижение свойств в конструкторе | свойства и присваивания вручную |
| `[$a, $b] = $pair` | `list($a, $b) = $pair` |
| `[...$a, ...$b]` | `array_merge($a, $b)` |
| `$x ??= 0` | `$x = $x ?? 0` |
| `catch (A \| B $e)` | два блока `catch` |
| `str_contains($s, $part)` | `strpos($s, $part) !== false` |
| `str_starts_with($s, $part)` | `strpos($s, $part) === 0` |
| `foo(a: 1, b: 2)` | обычные аргументы по порядку |
| `json_decode(…, JSON_THROW_ON_ERROR)` | проверка `json_last_error() !== JSON_ERROR_NONE` |
| `throw` внутри выражения | обычный `if` и `throw` отдельной строкой |
| `enum` | класс с константами |
| `readonly` | `private` и метод чтения |
| запятая после последнего аргумента или параметра | убрать |

Большинство строк — механическая замена. Ниже — четыре, в которых легко ошибиться.

### Стрелочная функция: не забыть use

Стрелочная функция сама видит переменные снаружи. Обычная анонимная — нет: всё нужное перечисляется в `use`.

```php versions
$rate = 1.2;
$prices = [100, 250];

$withUse = array_map(function ($price) use ($rate) {
    return $price * $rate;
}, $prices);

$withoutUse = array_map(function ($price) {
    return $price * $rate;
}, $prices);

print_r($withUse);
print_r($withoutUse);
```

Без `use` код не падает — получается замечание о неизвестной переменной (в PHP 8 — предупреждение) и нули в результате. На сервере, где замечания скрыты, это выглядит как «цены обнулились».

### match: три отличия от switch

```php
// PHP 8
$label = match ($status) {
    'new' => 'Новый',
    'paid', 'sent' => 'В работе',
    default => 'Неизвестно',
};
```

```php
// PHP 7.0
switch ($status) {
    case 'new':
        $label = 'Новый';
        break;
    case 'paid':
    case 'sent':
        $label = 'В работе';
        break;
    default:
        $label = 'Неизвестно';
}
```

1. `match` возвращает значение, `switch` — нет: результат нужно присвоить в каждой ветке.
2. `match` сравнивает строго, `switch` — нестрого. Для строковых ключей вроде `'new'` разницы нет, для чисел и строк с цифрами — есть.
3. `match` без `default` бросает ошибку, если ничего не подошло. `switch` молча идёт дальше. Если исходный `match` был без `default`, в `switch` его нужно добавить и бросить исключение самому.

Когда `match` просто сопоставляет значению значение, лучшая замена — не `switch`, а массив:

```php
$labels = ['new' => 'Новый', 'paid' => 'В работе', 'sent' => 'В работе'];
$label = $labels[$status] ?? 'Неизвестно';
```

### Nullable-тип без знака вопроса

Записи `?int` в 7.0 нет. Но параметр со значением по умолчанию `null` принимает `null` — это и есть способ объявить «число или ничего»:

```php
function setDiscount(int $percent = null)   // в PHP 7.0 — то же, что ?int $percent = null
{
    // …
}
```

Для типа результата такого приёма нет. `: ?int` приходится убирать совсем, а что функция возвращает, писать в комментарии:

```php
/**
 * @return int|null
 */
function findPrice(array $menu, string $title)
{
    return $menu[$title] ?? null;
}
```

Такие комментарии называют докблоками. В старом коде это единственная запись о типах — и редактор, и следующий читатель полагаются на неё. Убрал тип из сигнатуры — перенеси его в докблок.

### Класс: развернуть конструктор

```php
// PHP 8
class Product
{
    public function __construct(
        private string $title,
        private ?int $price = null,
    ) {}
}
```

```php
// PHP 7.0
class Product
{
    /** @var string */
    private $title;

    /** @var int|null */
    private $price;

    public function __construct(string $title, int $price = null)
    {
        $this->title = $title;
        $this->price = $price;
    }
}
```

Три действия: объявить свойства, убрать слова `private` из параметров, дописать присваивания. И не забыть запятую после последнего параметра — в 7.0 это ошибка разбора.

## Вниз: порядок работы

1. **Зафиксировать поведение на новой версии.** Тесты или хотя бы сохранённый вывод для нескольких входных данных.
2. **Проверить разбор на старой версии.** PHP сообщает только о первой синтаксической ошибке: исправил — запустил снова. Так, пока файл не разберётся целиком.
3. **Выполнить код.** Отсутствующие функции (`str_contains`) при разборе не видны — они проявятся только во время выполнения, и только в тех ветках, до которых дошло дело.
4. **Сравнить результат** на двух версиях с тем, что зафиксировано в первом пункте.

На платформе второй и третий пункты — это кнопка «Запустить» с выбором «Обе версии рядом».

## Вверх: осовременить, не сломав

Здесь главный риск другой: новый синтаксис не только короче, он ещё и **строже**. Замена «один в один» может изменить поведение.

Безопасный порядок — от замен, которые ничего не меняют, к тем, что меняют:

1. **Тесты.** Без них любая «чистка» — игра вслепую.
2. **Чисто внешние замены.** `array()` → `[]`, `list()` → `[]`, `isset($a) ? $a : $b` → `$a ?? $b`, анонимная функция → стрелочная, `strpos(…) !== false` → `str_contains(…)`. Поведение прежнее.
3. **Типы результата.** Функция сама отвечает за то, что возвращает, поэтому риск невелик.
4. **Типы параметров.** Это уже проверка, которой раньше не было. Нужно знать, что на самом деле передают вызывающие.
5. **`switch` → `match`.** Сравнение становится строгим, отсутствие ветки — ошибкой.
6. **`declare(strict_types=1)`** — в последнюю очередь и по одному файлу.

Тип у параметра — не украшение, а условие:

```php versions
function lineTotal(int $price, int $qty)
{
    return $price * $qty;
}

echo lineTotal(250, '2'), "\n";     // строка из формы — подходит, станет числом
echo lineTotal(250, ''), "\n";      // пустое поле — TypeError
```

Пока типов не было, пустое поле давало ноль (или падало в PHP 8 уже на умножении). С типом функция отказывается работать ещё на входе. Часто это и есть цель — но тогда вызывающий код должен быть к этому готов.

> **Одна правка — одна цель.** Не смешивай осовременивание с исправлением ошибок и новыми возможностями. Если после «чистки» что-то сломалось, ты должен быть уверен, что дело в чистке. В системе контроля версий это отдельные коммиты.
