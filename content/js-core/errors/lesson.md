# Ошибки и try/catch

В блоке «Как писать с нуля» мы учились читать ошибки. Теперь научимся ими управлять: создавать свои и перехватывать чужие.

## Бросить ошибку

Если функция получила данные, с которыми не может работать, честнее всего сразу об этом сообщить.

```js
function divide(a, b) {
  if (b === 0) {
    throw new Error('Деление на ноль');
  }
  return a / b;
}
```

`throw` немедленно прерывает функцию — и ту, что её вызвала, и так далее вверх, пока ошибку кто-нибудь не перехватит. Если не перехватит никто, программа остановится.

Почему не вернуть `null` или строку `'ошибка'`? Потому что вызывающий код может забыть это проверить и продолжит считать с мусором. Ошибку забыть нельзя.

## Перехватить ошибку

```js
try {
  const data = JSON.parse(text);     // может бросить SyntaxError
  console.log(data.name);
} catch (error) {
  console.log('Не удалось разобрать:', error.message);
} finally {
  console.log('Выполнится в любом случае');
}
```

- Если в `try` случилась ошибка, выполнение сразу прыгает в `catch`. Оставшиеся строки `try` пропускаются.
- `finally` выполняется всегда — с ошибкой или без. В нём убирают за собой: закрывают файл, прячут индикатор загрузки.

У объекта ошибки есть `name` (тип), `message` (текст) и `stack` (цепочка вызовов).

## Свои типы ошибок

Чтобы отличать одни ошибки от других, создают собственные классы:

```js
class ValidationError extends Error {
  constructor(message, field) {
    super(message);
    this.name = 'ValidationError';
    this.field = field;
  }
}

try {
  saveUser(form);
} catch (error) {
  if (error instanceof ValidationError) {
    showFieldError(error.field, error.message);   // ожидаемая ошибка — показать пользователю
  } else {
    throw error;                                   // неожиданная — пробросить дальше
  }
}
```

## Где перехватывать

Перехватывай ошибку там, где знаешь, **что с ней делать**: показать сообщение, подставить значение по умолчанию, повторить попытку. Если не знаешь — не перехватывай, пусть летит выше.

Три вещи, которых делать не стоит:

```js
try { doWork(); } catch (error) { }                  // проглотить: ошибка есть, но о ней никто не узнает

try { doWork(); } catch (error) { return null; }     // спрятать причину: теперь непонятно, что сломалось

try { /* сто строк */ } catch (error) { ... }        // ловить всё подряд: в catch попадут и твои опечатки
```

Пустой `catch` — худший вариант: программа работает неправильно и молчит. Отлаживать такое очень трудно.

## Проверка на входе

Хорошая привычка — проверять аргументы в начале функции и бросать ошибку с понятным текстом. Это тот же «ранний выход», только для недопустимых данных.

```js
function setAge(user, age) {
  if (typeof age !== 'number' || Number.isNaN(age)) {
    throw new TypeError('Возраст должен быть числом');
  }
  if (age < 0) {
    throw new RangeError('Возраст не может быть отрицательным');
  }
  user.age = age;
}
```

В сообщение включай то, что поможет найти причину: какое значение пришло, в какой строке файла, для какого поля.
