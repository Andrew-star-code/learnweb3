# Модули

Пока весь код лежит в одном файле, с ним можно работать до нескольких сотен строк. Дальше нужна структура. Модуль — это файл, который явно говорит, что он отдаёт наружу и что берёт у других.

## export и import

```js
// price.js
const TAX = 0.2;                           // не экспортирована — видна только в этом файле

export function withTax(price) {
  return price * (1 + TAX);
}

export function formatPrice(price) {
  return `${price.toFixed(2)} ₽`;
}
```

```js
// cart.js
import { withTax, formatPrice } from './price.js';

console.log(formatPrice(withTax(100)));    // '120.00 ₽'
```

Всё, что не помечено `export`, остаётся внутри файла. Это ещё один способ спрятать детали — как приватные поля у классов.

### Экспорт по умолчанию

У модуля может быть один «главный» экспорт. Он импортируется без фигурных скобок, имя при импорте выбираешь сам.

```js
// User.js
export default class User { /* ... */ }

// app.js
import User from './User.js';
```

Именованные экспорты надёжнее: имя одно и то же во всём проекте, редактор подсказывает его и находит все использования. `export default` обычно оставляют для файлов, где экспортируется ровно одна сущность — например, класс.

### Ещё несколько форм

```js
import { withTax as addTax } from './price.js';   // переименовать при импорте
import * as price from './price.js';              // всё разом: price.withTax(...)
```

## Что нужно знать о поведении модулей

- Код модуля выполняется **один раз**, при первом импорте. Все, кто импортирует модуль, получают одно и то же.
- У каждого модуля своя область видимости. Переменные верхнего уровня не попадают в глобальную область и не конфликтуют с соседними файлами.
- Путь в `import` — относительный и начинается с `./` или `../`. В браузере расширение `.js` обязательно.

## Подключение в браузере

```html
<script type="module" src="app.js"></script>
```

Достаточно подключить один входной файл — остальные браузер загрузит сам по цепочке импортов. Без `type="module"` слова `import` и `export` вызовут синтаксическую ошибку.

Модули не работают, если открыть HTML-файл двойным щелчком (адрес начинается с `file://`). Нужен веб-сервер — хотя бы `php -S localhost:8000`.

## Легаси: CommonJS и скрипты без модулей

В старом коде ты встретишь две другие системы.

**CommonJS** — исторический формат Node.js:

```js
const { withTax } = require('./price');    // вместо import
module.exports = { withTax };              // вместо export
```

**Обычные скрипты** — несколько тегов `<script>` подряд, где все файлы делят одну глобальную область. Порядок подключения важен, а две переменные с одним именем в разных файлах конфликтуют. Именно так устроены сайты на jQuery.

## Как делить код на модули

- **По смыслу, а не по типу.** Файлы `cart.js`, `price.js`, `user.js` понятнее, чем `functions.js`, `helpers.js`, `utils.js`.
- **Отделяй вычисления от ввода-вывода.** Функции, которые считают и преобразуют, кладут отдельно от кода, который работает со страницей, сетью или файлами. Первые легко проверять тестами, вторые — нет.
- **Зависимости в одну сторону.** Если `a.js` импортирует `b.js`, а `b.js` импортирует `a.js`, границу между ними стоит провести иначе.
- **Экспортируй минимум.** Чем меньше модуль отдаёт наружу, тем свободнее ты можешь менять его внутри.

> Редактор платформы выполняет один файл, поэтому в этом уроке нет заданий с `import` и `export` — только вопросы и план. Настоящие модули появятся в блоке «JavaScript в браузере», где проекты состоят из нескольких файлов.
